# Pixi proof status

- PixiJS 8.22.0 (MIT); original image generated for this proof with OpenAI image generation. The three-second 15 fps H.264 test video was generated locally from that image with FFmpeg; it is a technical decoding fixture, not licensed footage or a finished creative asset.
- Auto-play and auto-update are disabled on the Pixi video texture. Sampled repeated frames passed a Chromium equality test after that change.
- Headless Chromium used SwiftShader; 150 frames without video took 65.1 s, of which the combined canvas capture/encode call took 65.0 s. With video, 150 frames took 71.8 s including 2.80 s of seeking and 68.9 s in capture/encode. A separate 30-frame gl.readPixels probe took 6.97 s. JavaScript render timing excludes deferred GPU work.
- Headed Brave used the Intel Iris Plus 645. The same 30-frame readback probe took 0.658 s. Before correction, 150 video frames took 2.02 s, including 1.92 s seeking. The fixed 15 fps fixture now seeks only once for each pair of 30 fps output frames: 150 frames took 1.29 s, including 1.10 s seeking. These are single runs, not statistical benchmarks.
- A headed Brave export through the existing browser encoder completed a 450-frame 1080 x 1920 H.264/AAC 15-second MP4 in 4.97 s using silent synthetic audio. The headless 220-second timeout and hardware result are different browser configurations; this is not a direct before/after of the seek change alone.
- The JavaScript heap readings in the benchmark are not peak process or GPU memory. Encoder calls include canvas capture/conversion/backpressure; these costs were not separated. AAC processing and muxing were not separately profiled.
- The isolated editor option uses the clip-bound Music Analysis v1 timeline and approved cues. Controlled tests cover the visual workflow, no lyric requests in Visual mode, selected-audio marker, timed text and sampled preview/export frames; a real-song test and product-owner visual review are still required.
- Creative expansion adds three bounded image treatments and an optional device-local footage layer. The selected footage is never uploaded or committed; the artist's selected song remains the exported audio. Footage is sampled by clip-relative browser media seeking, without assuming 15 fps. Its reveal uses a verified beat when available and a deterministic fallback otherwise.
- A local test using the user-authorized 30 fps, 576 × 576 clip produced a 15-second 1080 × 1920 H.264/AAC MP4 in 5.80 seconds on hardware-backed Brave; three sampled preview/export frames averaged 2.70/255 RGB error. Test audio was synthetic. Arbitrary codecs, variable frame rates and all hardware remain unverified.

## Full-frame user media correction

The customer path uses one locally selected MP4 or WebM (maximum 250 MiB), centered and cropped to fill the vertical frame. Short videos loop. The scene uses the existing clip-relative beat and energy data for restrained scaling and light response; it does not infer subject position. The original demo art is not visible behind supplied footage. Rendering and export use the same frame evaluator; user media is not uploaded or committed. Multiple media, subject-aware framing, and automatic selection remain future work.

The prior fixture route returned a full HTTP response to seek requests, which caused the browser to remain at the first frame; earlier measurements using that route did not prove moving-footage export. The corrected tests load the explicitly cleared local file as a browser Blob, as the product does. In a hardware-backed Intel Mac run, sampled seeks changed and repeated successfully, a 450-frame H.264/AAC export completed in 15.08 s, and sampled preview/export mean RGB error was 2.73/255. This is a single-asset measurement, not a guarantee for other codecs, machines, or variable-frame-rate video.
