# MUMOO creative engine

Turns a song into short 9:16 music-ad creatives. Every creative is a lyric video. The browser stays light: heavy work (lyrics, analysis, video rendering) runs in the cloud.

## The flow

1. **Upload** a song (MP3, M4A/AAC, WAV, FLAC, OGG/Opus, AIFF…) and pick the genre. The file is sniffed by its bytes, decoded in the browser and identified by a SHA-256 hash. Only title, artist and the embedded cover art are read; the cover is turned into a few colour numbers (palette, brightness, saturation, warmth) in the browser and the picture itself is never kept or uploaded.
2. **Your clip.** Drag the 15-second window on the waveform. The same page gets the lyrics: *transcribe* or *sync* typed words, in any language, then fix words in the editor and sync again. Lyrics come from `audio-intelligence/modal_lyrics_v2_staging.py` (Whisper + forced alignment) through the `transcribe-lyrics*` Netlify functions.
3. **Creatives.** As soon as the words are final, our own model reads what they mean (`lyric-meaning-cloud.ts` → `read-lyric-meaning*` functions → `modal_lyric_meaning_staging.py`); only three codes come back (attitude, sadness, intensity). The song data (genre, music analysis, lyric meaning, cover) goes to the "brain" (`creatives-pack.ts`, `readSong`), which picks the pictures, looks, type and motion. Genre and tempo choose the lane; the attitude of the words picks the library pictures (`library-pick.ts`), and among those that fit, pictures in the colours the genre calls for come first (`coloursFor`, `colourFit`; each picture's colours are measured on our server) and grades the chosen look: sad words give duller, cooler, darker colours and softer beat hits, confident ones warmer and punchier (`mood-grade.ts`, applied in `pack-renderer.ts`, so previews and cloud exports match). When the file has a cover, the baked photography effects closest to its colours lead (`coverFit` in `look-fit.ts`). What people play, keep and download is learned per lane (`brain_feedback`, `learnedShelf`): it orders the templates on the shelf (`shelfOrder`), picks which card each template leads with and which library pictures it draws. Previews are drawn with Pixi/WebGL.
4. **Export.** `encode-creative*` Netlify functions start a Modal job that renders the frames with `render.html` (`pack-render-page.ts`) and encodes the MP4 with the song audio.

Staging access is gated by an HMAC token (`netlify/lib/access.mjs`). There are no rate limits: the product is paid, so usage is paid for.

## Run locally

Node 22.17.1.

```sh
npm ci
npm run dev
```

The cloud steps need the Netlify functions and the Modal apps (`audio-intelligence/README.md`). Deploy to staging:

```sh
npm run build
npx netlify-cli deploy --prod --dir=dist --functions=netlify/functions --site=097cfd7a-2b9e-4b7c-9ad2-4092e6694dc5
```

## Checks

```sh
npm run typecheck
npm run lint
npm test
```

`npm test` runs unit tests and the headed product-flow test (`MUMOO_HEADED=1`, macOS, local Brave/Chrome). The product-flow test mocks the network at the Netlify boundary (and serves a few ffmpeg test-pattern photos as the library) and walks upload → clip → lyrics → creatives.

Email: every letter is in `netlify/lib/letters.mjs` and goes out through Resend (`mail.mjs`) from "mumoo <moo@mumoo.app>": always "mumoo" in lowercase, never "app", no name and no address in the body, a code always in the subject. Neon's sign-in codes come to us too: Neon Auth's `send.otp` webhook calls `/api/auth/email` (`auth-email.mjs`, checked against Neon's signing keys in `neon-webhook.mjs`), and a sign-in waits for it, so if it is down nobody can sign in. The daily `inactivity` function sends the 60- and 83-day reminders (files go at 90 days) and the storage letter (`storage-warning.mjs`: once past 90% of the 5 GB, again only after dropping under 80%). Deleting an account sends a last letter saying it is done.

## Decisions worth knowing

- Cue contract: at most 120 cues, text up to 48 characters, whole milliseconds, ordered, ending inside the 15 seconds. A cue takes effect on the first frame at or after its start (ceiling division); browser playback shows the frame at or before the audio playhead (floor division).
- The preview and the cloud render run the same Pixi renderer (`pack-renderer.ts`), so what you see is what is encoded.
- The model reads the words in any language it knows (Qwen3 covers 119). Clips with too little text (chants, one phrase) read as neutral. Whisper sometimes mislabels the language of African-language chants; the meaning step is not misled by that, but the label is shown to the creator.
- Inter Variable (UI and type) is bundled with its SIL OFL licence; display faces are bundled `@fontsource` fonts.
- Every visit starts clean. Nothing of a run (song, genre, clip, lyrics) survives a refresh; only the cart does. The person's own pictures stay in their account (History → Uploads) until they delete them, but the shelf draws only those added in this run (`mine` in `use-uploads.ts`, up to ten at once); a refresh or Start over just empties it. The account keeps at most 500 pictures (`MAX_KEPT_PICTURES`) within its 5 GB allowance. `forget-session.ts` removes what an older version left in the browser.
- "My song has no lyrics" (step 2): for instrumental songs or only sounds. Nothing is transcribed or read (no cloud cost), `profile.noLyrics` is set, and the creatives page shows only the rows that work without words (`rowsFor` in `creatives-pack.ts`: everything but Window and Pulise), with no words and no Lyrics switch. Window and Pulise are made of the lyrics, so they are not dealt, painted or rendered. Feedback records `lyrics_origin = 'none'`. Choosing another song, or Start over, turns it off.
